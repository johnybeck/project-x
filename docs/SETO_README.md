# SETO — стенд сравнения вариантов размещения поликлиник

> Если ты только подключился к проекту — сначала [HANDOFF.md](HANDOFF.md).

Код эксперимента из пропозала v2: какое качество размещения даёт конвейер с VLM
по сравнению с простыми геометодами и что вносит каждая часть системы. Сейчас
работаем только по Мадриду, другие города добавятся позже.

Это **не продукт**, а стенд: он должен не «выбирать места», а честно мерить
и сравнивать. Отсюда все решения в коде — один расчёт метрик на все варианты,
одинаковые ограничения, фиксация протокола, запрет подмены одного варианта
другим.

## С чего начать

```bash
pip install -r requirements.txt     # Python 3.11; pulp должен быть < 4
cp .env.example .env                # и вписать значения, см. ниже
python -m seto doctor madrid        # конфиги, git, данные, ключ, зависимости
python -m seto acquire madrid --snapshot-date 2026-10-28   # источники в raw/, с хешами
python -m seto prepare-city madrid                         # подготовка города, 2,5 минуты
python -m seto step2 madrid <папка prepare-city>           # всё, что считается без модели, 43 минуты
python -m seto ahp-stability madrid <папка prepare-city>   # устойчивость E, 3 секунды
python -m seto acquire-imagery madrid <папка prepare-city> # снимки, около 2 часов
pytest tests/                                              # 556 тестов, около 2 минут
```

Дальше нужен сервер модели. Порядок обязателен: одна клетка, потом 10, потом город.

```bash
python -m seto score-sample madrid <папка prepare-city> --mode text --cells 1
python -m seto score-sample madrid <папка prepare-city> --mode image --cells 1
python -m seto run-city madrid --with-image
python -m seto report <папка run-city>
python -m seto m4 madrid <папка prepare-city> <папка run-city>/scores_image.parquet
```

`run-city` заново делает подготовку города в новой папке прогона, скоринг берёт из
кэша, если он уже считался.

Результат считается после заморозки и только с `--protocol`:

```bash
python -m seto freeze-protocol
python -m seto run-city madrid --with-image --protocol protocol/protocol.json
python -m seto step2 madrid <папка run-city> --scores <папка run-city> --protocol protocol/protocol.json
```

`--protocol` сверяет коммит, чистоту дерева, модель, промпт, параметры, правила города и
данные, у `step2` ещё и манифесты папок, из которых он читает. При расхождении команда
отказывает с причиной и кодом 3. Протокол записывается во входы манифеста прогона. Папка
`protocol/` стоит в `.gitignore`: файлы протокола в git-дереве сделали бы его грязным, а
их коммит сменил бы коммит протокола.

`snapshot_date` города в `madrid.yaml` и дата папки в `raw/` обязаны совпадать.
`acquire` конфиг не читает: без `--snapshot-date` он кладёт данные в папку с
сегодняшней датой, а остальные команды ищут их по дате из конфига.

`acquire` качает всё, что прописано в `sources` конфига города: OSM, тайл GHS-POP,
реестр, падрон, участки, доход, кадастр. Снимки качает `acquire-imagery`, ей нужна папка
`prepare-city` с сеткой. Исходный файл кадастра передавать нельзя, каждый участник
качает его сам (`docs/MADRID_DATA.md`, п. 8).

## Что нужно в `.env`

```
MODELS_BASE_URL=http://10.100.11.205/v1
MODELS_API_KEY=<ключ внутренних моделей>
SETO_DATA_ROOT=/path/to/seto-data  # вне синхронизируемой папки: там десятки гигабайт
SETO_BIND_SOURCE_IP=<ip Wi-Fi>     # только если VPN забирает весь трафик
```

Последняя строка нужна, если на машине включён VPN «на весь трафик»: он
перехватывает маршрут до внутреннего сервера лаборатории. Правильное решение —
split-tunnel; это обход на случай, когда его нет.

## Сравниваемые варианты

| | что делает | что показывает |
|---|---|---|
| **A** | 1000 случайных допустимых наборов | нижняя планка |
| **B** | P-median, веса = население | вклад оптимизатора и данных о населении |
| **BN** | P-median, веса = нуждаемость | эталон для М2, ценность знания о нуждаемости |
| **M** | максимальное покрытие | верхняя граница по главной метрике |
| **C** | та же VLM, вход — текст из OSM и кадастра | оценщик без изображения |
| **D** | та же VLM, вход — снимок 25 см | проверяемая система |
| **D10** | то же, вход — снимок Sentinel-2, 10 м | вклад разрешения |
| **CN, DN** | C и D поверх нуждаемости | насколько скор сдвигает BN, описательно |
| **E** | GIS-AHP по Dutta et al., выбор по пригодности | практика GIS-AHP |
| **EN** | E с критерием нуждаемости | AHP с тем же знанием, что у метрики |
| **EP** | пригодность EN в весе P-median | снимок против критериев при одном решателе |

Модель отвечает не скором, а подоценками видимого. Скор получается из них по
заранее заданному правилу и входит ровно одним способом — множителем веса спроса
`w = P·(1 + α·ŝ)`, где `ŝ` — min–max нормировка по всем клеткам города. При α = 1
вес клетки растёт не больше чем вдвое. Площадки скор не фильтрует и не штрафует.
Поэтому разница **D − C** означает вклад именно изображения: оценщик, промпт и всё
остальное у них общее, различается только вход.

## Где что лежит

```
seto/
  acquire/   загрузка сырых данных, чтение PBF
  data/      граница, сетка, население, демография, реестр, кадастр, доход, признаки
  routing/   пешеходный граф, привязка, матрица времён
  sites/     допустимые площадки и общие ограничения
  scoring/   промпт, вызов модели, правило перевода, веса спроса
  variants/  решатели, GIS-AHP, приём внешнего E
  metrics/   покрытие, адресность, 2SFCA, М2, М4 — один код на все варианты
  costs/     таймеры и журнал человеко-времени
  experiment/ подготовка, варианты, шаг 2, устойчивость E, протокол, пакет
  imagery/   снимки: WMS PNOA, сцена Sentinel-2, swisstopo
  report/    таблицы и отчёт
  qa/        карты и инспектор для визуальной проверки
```

Данные и прогоны лежат вне репозитория, в `SETO_DATA_ROOT`:
`raw/<город>/<дата>/` только на чтение, `runs/<город>/<run_id>/` не
перезаписывается, `cache/vlm/<режим>/` — ответы модели, `human_log.csv` —
журнал `log-human`. Снимки лежат в `raw/<город>/<дата>/imagery/<набор>/<cell_id>.png`,
по одному на клетку.

## Чего стенд НЕ делает — и почему

- **не считает порог допустимой потери δ.** Обоснования нет, пилот описательный;
- **не выводит среднее `A_i` по 2SFCA.** При одинаковом k оно равно общей
  мощности делить на население и от размещения не зависит — метрика выглядела
  бы осмысленной и не мерила бы ничего;
- **не подменяет вариант D вариантом C,** когда снимков нет, и не считает частичный D.
  Критерий качества определён через D, и отчёт честно пишет «нет данных»;
- **не чинит импортированное решение E.** Нарушение — отказ с причиной;
- **не ставит «выполнен» критериям пилота без D.** Все три критерия определены через D,
  затраты и надёжность читаются из журнала: нет записей — «нет данных»;
- **не использует расстояния по прямой** нигде в решениях и метриках.
