## 1. Обозначения

| | |
|---|---|
| `i` | клетка спроса — **все** клетки города, включая запрещённые для размещения |
| `j` | допустимая площадка |
| `E` | существующая общественная сеть; в Мадриде 131 центр здоровья из реестра |
| `S` | набор новых объектов, `|S| = k` |
| `P_i` | всё население клетки, включая детей |
| `N_i` | нуждаемость клетки, раздел 1.1 |
| `t_ij` | время пешком от клетки `i` до объекта `j`, минуты |
| `t_i^E` | время до ближайшего существующего учреждения |
| `N_E` | число существующих учреждений |

Время до ближайшего учреждения после добавления `S`:

```
t_i(S) = min( t_i^E , min_{j ∈ S} t_ij )
```

Недостижимое время ограничивается сверху `t_max = 60 мин`.

### 1.1. Население и нуждаемость

Пропозал берёт `P_i` из растра GHS-POP. В Мадриде это отступление: итоги по участкам —
падрон, внутри участка жители лежат по квартирам кадастра, растр только у 3 участков
(`population.method: registry_by_dwellings`). Причины — `docs/MADRID_DATA.md`, п. 6 и 9.

Нуждаемость — только по внешней статистике, одна на все варианты:

```
N_i = P_i^(18–64) + r · P_i^(65+)
```

Доли групп переносятся на клетки внутри наименьшей открытой единицы, в Мадриде это
переписной участок. Инвалидность, хронические болезни и доход в `N_i` не входят.

### 1.2. Вес спроса и решение

| вариант | вес `w_i` или правило |
|---|---|
| A | 1000 случайных допустимых наборов |
| B | `w_i = P_i` |
| BN | `w_i = N_i` |
| M | `S* = argmax Σ_i P_i · 1[t_i(S) ≤ T]` |
| C, D, D10 | `w_i = P_i · (1 + α · ŝ_i)`, скор по тексту, снимку 25 см, снимку 10 м |
| CN, DN | `w_i = N_i · (1 + α · ŝ_i)`, скор по тексту и по снимку 25 см |
| E, EN | площадки с наибольшей пригодностью AHP при общих ограничениях |
| EP | `w_i = P_i · (1 + α · q̂_i)`, `q` — пригодность AHP на весах EN |

```
ŝ_i = (s_i − min s) / (max s − min s)      по ВСЕМ клеткам города, включая пустые
```

`s_i` — балл по заранее заданному правилу из подоценок модели. Для `N_возр` это правило
`age`: эпоха «до 1955» — 3, «1955–1975» — 2, «1975–2000» — 1, «после 2000» — 0, «не
определить» — 1,5. При α = 1 вес лежит в `[P_i, 2·P_i]`; клетка без жителей получает
вес 0 при любом скоре. Клетка без ответа модели получает медиану скоров города
(`imputed`). Признак вне списка допустимых — не сбой: он становится «не определить»,
остальные признаки ответа остаются (Д24).

Решение B, BN, C, D и их модификаций: `S* = argmin Σ_i w_i · t_i(S)`. При k ≤ 2 — полный
перебор допустимых пар, ничья — меньшая пара индексов. При k = 5 и 10 — эвристика обмена
с 20 случайных стартов.

### 1.3. GIS-AHP

Пять критериев Dutta et al. (2022): расстояние до существующих учреждений, трущоб,
главных дорог, плотных районов, бедных районов. Трущобы и бедность исключаются.

| вариант | веса | критерии |
|---|---|---|
| E | 0,567 / 0,257 / 0,176 | сеть, дороги, плотные районы |
| EN | 0,388 / 0,176 / 0,121 / 0,315 | сеть, дороги, плотные районы, нуждаемость (доля 65+) |

Дальше от сети, ближе к дорогам и плотным районам — лучше. Расстояния по сети, квартили
1–4 по допустимым клеткам, ничьи — по населению в радиусе T. Веса Dutta не меняются ни в
одном городе. Наши решения, которых нет в статье, — `docs/RESULTS.md`, прогон 8.

## 3. Первичные метрики

Их две, по одной на вопрос. Остальное — вторичное и описательное.

### 3.1. Качество размещения: ΔCov_T

```
Cov_T(S) = 100 · Σ_i P_i · 1[t_i(S) ≤ T] / Σ_i P_i          проценты

ΔCov_T   = Cov_T(S) − Cov_T(∅)                              процентные пункты

ΔN_T     = Σ_i P_i · ( 1[t_i(S) ≤ T] − 1[t_i^E ≤ T] )       жители
```

Больше — лучше. Смысл: сколько жителей получают учреждение в пешей доступности
благодаря новым объектам.

**Знаменатель — всё население города**, включая жителей непривязанных и недостижимых
клеток. Уменьшать знаменатель на «проблемные» клетки нельзя: это завысило бы покрытие.

**Множитель 100 обязателен** — метрика в процентах, разницы в процентных пунктах.

У метрики два ограничения: она бинарна и считает всех жителей одинаково. Поэтому она не
может наградить вариант за знание о том, кому учреждение нужнее. Это закрывают М1–М4.

### 3.2. Вклад изображения: М2, ошибка замещения и доля захвата

```
Z_N(S)   = Σ_i N_i · t_i(S)                      человеко-минуты нуждающихся
потолок  = Z_N(S_B) − Z_N(S_BN) ≥ 0              и в чел.-мин на 1000 нуждающихся
захват_X = (Z_N(S_B) − Z_N(S_X)) / потолок       проценты
порог    = 95-й процентиль |Z_N(S_B) − Z_N(S_B′)|
```

`B′` — P-median при `P_i × U[0,9; 1,1]`, 200 повторов. Считается при k = 1, 2, 5, 10 и
при всех определениях нуждаемости из конфига. **Захват показывается, только если потолок
выше порога шума.** Потолок около нуля значит, что снимку нечего закрывать.

Что М2 не мерит: внутри участка `N_i` постоянна, поэтому дизайн показывает, какую долю
знания статистики снимок восстанавливает без неё, но не пользу сверх неё. Порог шума не
ловит случайный захват: шум ±10 % гораздо уже канала скора, `docs/RESULTS.md`, прогон 8,
«Сколько может сдвинуть скор», и Д19 в `docs/OPEN_DECISIONS.md`.

## 4. Блок «адресность»

М2 — выше. Состав блока фиксируется при предрегистрации.

### 4.1. М1. Покрытие нуждающихся

`Cov_T` и `ΔN_T` с `N_i` вместо `P_i`. Отдельно считаются новые жители 65+ в зоне, в
людях: так М1 читается в пропозале, «+N жителей 65+ в 15 минутах».

### 4.2. М3. Равноценное время (эквивалент Колма — Поллака)

```
EDE = −(1/κ) · ln[ Σ_i N_i · e^(−κ · t_i(S)) / Σ_i N_i ]
κ   = ε · Σ_i N_i t_i / Σ_i N_i t_i²
```

`ε = −1`, проверка при −0,5 и −2. Меньше — лучше. **κ один на город и считается по
исходной сети:** иначе EDE разных вариантов оказались бы в разных шкалах.

### 4.3. М4. Видит ли модель

Сверка ответов модели с открытыми данными, до проверки размещения.

| | эпоха | достаток |
|---|---|---|
| мера | каппа Коэна | ранговая корреляция |
| эталон в Мадриде | самая частая эпоха жилых зданий кадастра в клетке | чистый доход на человека, ADRH 31097, 2023 |
| какие варианты | только D: текст C сам содержит год | C и D |
| клетки | не меньше 5 зданий и без ничьей, 812 клеток | клетки с доходом, 1253 |
| «не определить» | считается промахом; отдельно каппа без отказов и доля ответов | ранга не имеет, не входит |

Выше 0,4 у каппы — умеренное согласие. Разница 25 см и 10 м отвечает, нужно ли высокое
разрешение.

## 5. Дополнительные метрики (описательно)

### 5.1. Положение относительно A

Процентиль `ΔCov_T` варианта среди 1000 случайных наборов, строгий: доля наборов хуже.

### 5.2. Худшие 10 %

Среднее время доступа у 10 % населения с наибольшим временем, взвешенно по населению.
Клетка на границе отсечки 10 % учитывается **долей** своего населения.

### 5.3. Среднее время

```
T̄(S) = Σ_i P_i · t_i(S) / Σ_i P_i
```

**С оговоркой:** совпадает с целью P-median, поэтому приводится для полноты, а не как
независимая оценка B.

### 5.4. Дефицит доступности

```
Σ_i N_i · max(0, t_i(S) − T)        человеко-минуты
```

Видит сокращение пути, которое главная метрика не замечает.

### 5.5. Покрытие 65+ при медленной ходьбе

Доля жителей 65+ в 15 минутах при 60 м/мин. Считается пересчётом времён с потолком 60
минут; на графе Мадрида совпало с прямым расчётом до 3·10⁻¹¹ мин.

### 5.6. Джини и Тейль

Неравенство времени доступа, с весами `N_i`. Тейль раскладывается на «между районами» и
«внутри районов». Район клетки — район участка, давшего ей больше всего жителей.

### 5.7. 2SFCA (гауссово затухание, единая зона T)

```
G(t) = ( exp(−½·(t/T)²) − exp(−½) ) / ( 1 − exp(−½) )   при t ≤ T
G(t) = 0                                                 при t > T

Шаг 1:  R_j = S_j / Σ_{i: t_ij ≤ T} P_i · G(t_ij)
Шаг 2:  A_i = Σ_{j: t_ij ≤ T} R_j · G(t_ij)
```

Одна и та же `G` на обоих шагах, `S_j = 1`, считается с весами `P_i` и `N_i`.
Если знаменатель на шаге 1 равен нулю — `R_j = 0` и пометка.
Жители без учреждения в пределах `T` получают `A_i = 0` и входят во все показатели.

**Среднее `A_i` не выводится.** При равных мощностях взвешенное среднее равно общей
мощности учреждений, делённой на население, и при одинаковом k не различает размещения.

Что выводится вместо него:

- **доля населения с `A_i < A_0`**, где `A_0 = 0,5 · N_E / Σ_i P_i`, половина средней
  обеспеченности исходной сети; при весах N — то же с `Σ_i N_i`. Порог считается **по
  исходной сети один раз**;
- **10-й и 25-й процентили `A_i`**, взвешенные. Пока `Cov_T` < 75 %, оба равны нулю у всех
  вариантов. На Мадриде `Cov_15` = 86,5 %, поэтому нулевым остаётся только 10-й.

### 5.8. Расстояние до сети и недостижимые

Расстояние по сети от новых точек до ближайшего существующего учреждения: среднее и
минимум. Только описание, не критерий. Число жителей в клетках без маршрута — по каждому
городу отдельной строкой; на Мадриде 21 313.

## 6. Разницы между вариантами

По каждому городу в процентных пунктах **и** числе жителей. Порог δ не задаётся.
Знак: проверяемый вариант слева, «D − C», «C − B», а не алфавитное «B − C». Порядок задаёт
`CHAIN` в `experiment/evaluate.py`.

```
B − A          оптимизатор и данные о населении; у A берётся медиана
M − B          сколько покрытия теряет цель «среднее время» против цели «покрытие»
C − B          оценщик VLM без изображения
D − C          именно изображение: та же модель и тот же промпт
D − D10        разрешение снимка
BN − B         ценность знания о нуждаемости, потолок М2
CN − BN        насколько скор сдвигает решение BN, описательно
DN − BN        то же для снимка
D − E          MVP против практики AHP
D − EP         снимок против экспертных критериев при одном решателе
```

Если варианта нет, строка остаётся с пометкой «нет данных»: так видно, какая разница не
посчитана. `M` — верхняя граница, а не обычный конкурент: он оптимизирует ровно
оцениваемую метрику. D − E смешивает снимок и оптимизатор, её читают рядом с D − EP.

Строки `X − A (медиана)` дают для каждого варианта положение относительно A.

## 7. Критерии пилота

1. **Качество:** `ΔCov_T` варианта D **выше 95-го процентиля** случайного выбора A.
2. **Затраты:** активное время человека на подключение нового города у D —
   **не более половины** от E. В протоколе заранее указывается, что мерится у E:
   ручной процесс аналитика или алгоритм. Сейчас `pilot.e_cost_measure: algorithm`, ждёт
   подтверждения (Д18).
3. **Надёжность:** D дал допустимое решение **без ручной правки**; сбой — один
   перезапуск.

D не обязан быть лучше B по `ΔCov_T`: главная метрика взвешена всем населением, а D
намеренно отклоняет веса от `P_i`. Его вклад меряет М2, критерий 1 проверяет только, что
D не хуже случайного.

Пока D не считался, все три критерия — «нет данных». Подмена другим вариантом запрещена.
Затраты и надёжность читаются из журнала `log-human`; нет записей — «нет данных», а не
«выполнен». Таблица «если получится → вывод» — в п. 3.10 пропозала.

## 9. Краевые случаи

| ситуация | поведение |
|---|---|
| центроид клетки дальше 300 м от графа | «недостижимо» = `t_max`, непокрыта при любом `T`, **жители считаются** в знаменателе |
| нет маршрута до учреждения | то же |
| время подхода к узлу | прибавляется к маршруту: `snap_dist / walk_speed`, и у клетки, и у объекта |
| знаменатель 2SFCA шага 1 равен нулю | `R_j = 0` + пометка |
| нет учреждения в пределах `T` | `A_i = 0`, клетка входит во все показатели |
| `max s = min s` при нормализации скора | `ŝ ≡ 0` + пометка |
| невозможно выбрать `k` площадок | город помечается `k_reduced`, **все** варианты решают с наибольшим допустимым `k` |
| потолок М2 не выше порога шума | захват не показывается |
| потолок М2 меньше нуля | возможно только у эвристики, пометка `negative_ceiling`: повод проверить решатель |
| решение C или D совпало с B | статус `skipped_duplicate`, метрики всё равно считаются |
| решение BN совпало с B, CN или DN с BN | результат, а не дубликат |
| нет нуждаемости | BN, EN, EP, М1–М3 — «нет данных» |
| нет снимка хотя бы одной клетки | D — «нет данных», частичный D не считается |
| в клетке нет жителей | доля 65+ для EN равна 0 |
| равные значения критерия AHP | в лучший класс |

## 10. Приёмочные тесты реализации

- `Cov_T` монотонна по `T`; при `T ≥ t_max` равна 100.
- `ΔCov_T(∅) = 0`, `ΔN_T(∅) = 0`.
- Два близких объекта дают `ΔCov` **меньше** суммы их одиночных приращений
  (перекрытие видно численно). `ΔCov` — функция набора, не сумма по точкам.
- `ΔN_T` на ручном примере совпадает с подсчётом вручную.
- **Инвариант 2SFCA:** взвешенное населением среднее `A_i` равно
  `Σ_{j: R_j > 0} S_j / Σ_i P_i` с точностью `1e-9`.
- `A_i = 0` для клеток вне зоны `T`; `A_0 > 0` даже при нулевой медиане `A_i`.
- Метрики считаются одной функцией: подмена варианта не меняет код расчёта.
- Знаменатель `Cov_T` одинаков для всех вариантов и равен полному населению города.
- Потолок М2 при k ≤ 2 не меньше нуля; захват BN = 100 %, захват B = 0 %.
- Захват не показывается, если потолок не выше порога шума.
- При одинаковом времени у всех EDE равно этому времени, при разбросе больше среднего.
- Эвристика обмена при k = 2 совпадает с полным перебором.
- Отбор E на игрушечном городе совпадает с ручным расчётом.
- Отсутствующий вариант даёт в цепочке «нет данных», а не строку с нулём.

## 11. Что изменилось от v4 к v2 (для сверки)

Фиксирую, потому что часть кода и его комментарии писались по v4.

| | v4 | **v2 (действующая)** |
|---|---|---|
| города | выборка городов, разработка и проверка | три условия: Мадрид, Москва, Вашингтон; сейчас только Мадрид |
| варианты | A, B, M, C, D, E | **добавлены BN, CN, DN, D на двух разрешениях, EN, EP** |
| первичная метрика | `ΔCov_T` | **две:** `ΔCov_T` для качества, **М2** для вклада изображения |
| нуждаемость | нет | **`N_i`, r, определения устойчивости** |
| кого считает метрика | всех жителей | всех жителей **и блок «адресность» М1–М4** |
| `k` | 2 и 1 | **плюс 5 и 10 для М2**, эвристика обмена |
| ответ модели | скор 0–10 | **подоценки и правило перевода, заданное заранее** |
| текст C | без года и брендов | **год постройки и магазины сетей** |
| разрешение | ~1 м на пиксель | **переменная исследования:** 10 м и высокое |
| E | присылает внешняя команда | **своя реконструкция Dutta et al. с проверкой устойчивости** |
| разницы | D − M, D − B, D − C, D − E, D − A | **цепочка из 10 разниц** |
| затраты | D не больше половины E в каждом городе | то же, **и протокол заранее называет, что мерится у E** |
| `α` для устойчивости | только города разработки | **во всех городах** |
| базовая сеть | прокси по названиям в OSM | **официальные реестры** |
| частный сценарий | на цене жилья по объявлениям | **на доходе INE, ACS, после основного результата** |

Без изменений: определения `Cov_T`, `ΔN_T`, 2SFCA, канал `w = P·(1 + α·ŝ)`, ограничение
500 м, запрет порога δ, описательный режим.
